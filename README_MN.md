# JURA — juras.consulting / Hostinger VPS

Энэ багц нь JURA Consulting 2.0-ийн VPS-д зориулсан эх код, суулгах скриптүүд юм.
Үндсэн домэйн: https://juras.consulting
Серверийн шаардлага: Ubuntu 26.04 LTS, 4 GB RAM.

## Одоогийн төлөв

- Next.js / Node 24 хувилбарын production build шалгагдсан.
- SQLite болон локал файл хадгалалттай серверийн 87 интеграцийн шалгалт амжилттай.
- Харагдац, лого, зураг, бүх үндсэн интерфейсийг одоогийн эх кодоос хадгалсан.
- Нүүр, PERSONAL, WORK, KIDS, нэвтрэлт, админаас хэрэглэгч үүсгэх, байгууллага, даалгавар, зурагтай гүйцэтгэл, Academy, 5 асуулттай шалгалт, CMS багтсан.
- Docker/Caddy болон бодит VPS дээр суулгалт, DNS, сертификатын олголтыг энэ орчноос шалгаагүй. VPS рүү SSH сүлжээний холболт хүрээгүй.
- Cloudflare D1/R2 дахь одоогийн өгөгдлийг энэ багц автоматаар шилжүүлэхгүй. Энэ нь шинээр өгөгдлийн сан үүсгэнэ. Одоогийн хэрэглэгч, даалгавар, файлууд байгаа бол домэйны урсгалыг шилжүүлэхээс өмнө тусдаа экспорт/импорт шаардлагатай.
- Ямар ч бодит нууц үг, түлхүүр, хэрэглэгчийн өгөгдөл багцад байхгүй.

## 1. DNS

Домэйны DNS удирдлагад дараах зорилтот утгуудыг тохируулна:

| Төрөл | Нэр | Утга |
| --- | --- | --- |
| A | @ | VPS_IP_ADDRESS |
| CNAME | www | juras.consulting |

Ижил нэртэй хуучин A/CNAME болон IPv6 AAAA бүртгэл зөрчилдөж байгаа эсэхийг шалгана. Мэйлтэй холбоотой MX/TXT бүртгэлүүдийг хадгална. Cloudflare DNS ашигладаг бол эхний сертификатын шалгалтад DNS only хэрэглэж болно.
VPS-ийн сүлжээний дүрэмд TCP 80/443 нээлттэй байх шаардлагатай. SSH-ийн одоо ашиглаж буй портыг хадгална. Энэ багц firewall-ийг автоматаар өөрчлөхгүй.

## 2. GitHub-ээс VPS дээр суулгах

Hostinger-ийн Browser Terminal дотор дараахыг ажиллуулна. /opt/jura-consulting өмнө нь байгаа бол эхлээд агуулгыг нь шалгана. DNS хүснэгтийн VPS_IP_ADDRESS утгыг өөрийн серверийн IP хаягаар солино.

```bash
git clone https://github.com/davaasurenbattogtokh-cmyk/jura.git /opt/jura-consulting
cd /opt/jura-consulting
bash scripts/install.sh
```

Суулгагч Ubuntu 26.04 дээр шаардлагатай Docker Engine/Compose-ийг албан ёсны apt сангаас суулгана. Өмнө нь Docker байгаа бол түүнийг ашиглана. Docker-ийн зөрчилтэй багц, эсвэл 80/443 порт ашиглаж буй өөр үйлчилгээ байвал зогсож мэдээлнэ; тэдгээрийг устгахгүй.
Node.js-ийг серверт тусад нь суулгахгүй; Node 24 нь контейнерт ажиллана.

Анхны Juradmin нууц үгийг нууж оруулах асуулт гарна. Чатад тохирсон анхны нууц үгээ өөрийн терминалд оруулж болно. Зөвхөн hash хадгална. Дараагийн шинэчлэлт .env-ийг хадгална.

## 3. Шалгах

```bash
docker compose ps
docker compose logs --tail=50 app proxy
```

DNS зөв зааж, 80/443 нээлттэй бол Caddy HTTPS сертификатыг автоматаар авна.
https://juras.consulting/login хаягт Juradmin болон өөрийн оруулсан нууц үгээр нэвтэрнэ.
https://www.juras.consulting нь https://juras.consulting рүү шилжинэ.

### Домэйн ба нэвтрэлтийн засварыг одоо байгаа VPS дээр хэрэгжүүлэх

Өмнөх хувилбар `jura.consulting` гэсэн буруу домэйнтэй байсан. Зөв үндсэн домэйн
нь `https://juras.consulting`. Хуучин APP_URL нь зөв домэйноос ирсэн POST хүсэлтийг
403 алдаагаар хориглодог байсан. DNS нь шинэ домэйноор VPS рүү заасан байх ёстой.

```bash
cd /opt/jura-consulting
git pull --ff-only origin main
bash scripts/repair-access.sh --reset-admin
```

Скрипт өгөгдөл болон `.env`-ийг нөөцлөөд зөв APP_URL тохируулж, аппыг build хийнэ.
Проксиг дахин үүсгэж шинэ домэйны HTTPS тохиргоог ачаална. Дараа нь origin шалгалтыг
нэвтэрч байгааг бодит нууц үггүйгээр шалгаад шинэ Juradmin нууц үгийг хоёр удаа асууна.
Сервер дээрх өгөгдлийн эзлэхүүнийг хадгална. Нууц үгээ хадгалах бол `--reset-admin`-гүй ажиллуулна.
Хуучин домэйны эзэмшил баталгаажаагүй тул түүнд redirect эсвэл сертификат нэмээгүй.

### Зөвхөн нууц үгийг сэргээх

Нэвтрэх нэр `Juradmin`. Нууц үг нь суулгах үед терминалд оруулсан утга юм.
Нууц үг буруу гэсэн алдаатай бол серверийн терминалд:

```bash
cd /opt/jura-consulting
git pull --ff-only origin main
bash scripts/reset-admin.sh
```

Шинэ нууц үгийг хоёр удаа, тус бүр Enter дарж оруулна. Дэлгэц дээр харагдахгүй.
Нууц үг 10-аас доошгүй тэмдэгттэй байна. Контейнерийг дахин build хийх шаардлагагүй.
Скрипт өөрчлөлтөөс өмнө SQLite нөөц үүсгэж, зөвхөн одоо байгаа Juradmin админы
нууц үг/идэвхтэй төлөвийг шинэчлэн, түүний хуучин сессүүдийг хаана. Бусад хэрэглэгч,
даалгавар, файл хэвээр байна. Шинэ нууц үг чат, GitHub болон командын аргумент руу орохгүй.
`.env` дахь анхны нэвтрэлтийн hash өөрчлөгдөхгүй; шинэ нууц үг одоогийн өгөгдлийн санд хадгалагдана.
Хэт олон оролдлого гэсэн алдаатай бол 15 минут хүлээгээд нэвтэрнэ.
Сайт нээгдэхгүй, эсвэл серверийн алдаа гарвал нууц үг сэргээхийн оронд эхлээд
`docker compose ps` болон `docker compose logs --tail=50 app proxy` үр дүнг шалгана.

Footer-ийн утас, имэйл, хаяг болон хүсэлтийн мэдэгдэл хүлээн авах имэйл нь JURA-ийн өгсөн мэдээллээр анхнаасаа тохируулагдсан. Админы тохиргооноос өөрчилж болно. Өмнөх хувилбарт хоосон хадгалсан талбарууд шинэ анхны мэдээллийг ашиглана.

Турших: байгууллага → хэрэглэгч → даалгавар → хэрэглэгчээр гүйцэтгэх → админаас харах. Сургалтыг видео болон 5 бүрэн асуулттай нийтэлж туршина.
Сайт гаднаас нээгдэхэд нийтийн хуудсууд бүгдэд харагдана. Админ болон бусад кабинет серверийн эрхийн шалгалтаар хамгаалагдсан.

## 4. Өгөгдөл, файл, шинэчлэлт

Өгөгдлийн сан болон байршуулсан файлууд Docker-ийн jura_data эзлэхүүнд хадгалагдана.
`docker compose down -v` ажиллуулбал өгөгдөл устах тул ашиглахгүй.

Шинэ код байрлуулахын өмнө:

```bash
bash scripts/backup.sh
```

Энэ нь app/reminders-ийг богино хугацаагаар зогсоож SQLite, файлуудын нийцтэй snapshot болон .env-ийн хувийг /var/backups/jura-д хадгална. Нөөцийг серверээс тусдаа газарт давхар хуулна.

Git repository холбоотой бол:

```bash
bash scripts/update.sh
```

Эх кодын GitHub repository: https://github.com/davaasurenbattogtokh-cmyk/jura . CI/CD автомат байршуулалт хараахан идэвхжээгүй. .env, data, түлхүүрүүдийг Git-д нэмэхгүй.
Gitгүй үед шинэ release-ийн эх кодыг нөөцлөж байгаад шинэчилж, `bash scripts/install.sh`-ийг дахин ажиллуулж болно. .env болон Docker өгөгдлийн эзлэхүүнийг хадгална.

## 5. Имэйл болон сануулга

Суулгалт өөрөө имэйл илгээлтийг идэвхжүүлэхгүй. Одоогийн код Resend API ашиглана.

1. Resend дээр `juras.consulting` (эсвэл илгээх зориулалтын дэд домэйн)-ийг нэмээд тус үйлчилгээний өгсөн DNS бүртгэлүүдээр баталгаажуулна.
2. API түлхүүрээ зөвхөн VPS-ийн `.env` дотор `RESEND_API_KEY` утгад оруулна.
3. `EMAIL_FROM`-д баталгаажсан домэйны хаяг, жишээ нь `JURA <notifications@juras.consulting>` оруулна. Gmail-ийн хаягийг Resend-ийн илгээгчээр ашиглахгүй.
4. Админ → Тохиргоо → Админы мэдэгдлийн имэйл нь хүсэлт хүлээн авах хаяг. Анхны утга нь JURA-ийн холбоо барих Gmail хаяг; энэ нь илгээгчээс тусдаа.


.env дотор RESEND_API_KEY болон баталгаажсан EMAIL_FROM тохируулсны дараа:

```bash
docker compose up -d --force-recreate app reminders
```

Админ → Мэдэгдэл, имэйл хэсэгт тохиргооны төлөв, хүлээгдэж буй болон амжилтгүй мэдэгдлийг харна. "Илгээсэн" нь үйлчилгээ хүсэлтийг хүлээн авсныг заана; Inbox хүргэлтийг Resend-ийн бүртгэл болон хүлээн авагчийн имэйлээс баталгаажуулна. Түлхүүр, домэйн, VPS-ийн бодит хүргэлтийг энэ орчноос шалгаагүй. API-ийн амжилт, алдаа, дахин оролдлого болон давхар илгээлтээс хамгаалалтыг гадагш мэйл илгээхгүй тусгаарласан туршилтаар шалгасан.

Reminders контейнер эхлэхдээ болон цаг тутам хамгаалалттай maintenance endpoint-ийг дуудна. Өдрийн нэгтгэл Улаанбаатарын тохируулсан өглөөний цагаас хойш бэлтгэгдэнэ. Имэйл тохируулаагүй бол илгээсэн гэж тэмдэглэхгүй. Дата давхардуулахгүй түлхүүртэй.
MAINTENANCE_TOKEN-ийг суулгагч санамсаргүй үүсгэнэ. Энэ нь Sites-ийн service-access credential-ээс тусдаа; тэр credential энэ багцад байхгүй.
VPS дээр бүрэн шалгаж, өгөгдлийн шилжилт дууссаны дараа хуучин Sites сануулгыг зогсоож давхар үйлдлээс сэргийлнэ.
